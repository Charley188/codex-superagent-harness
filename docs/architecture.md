# 功能与架构

## 一条任务如何执行

1. 浏览器连接本地 HTTP 宿主，访问工作区和持久会话。
2. 普通聊天直接使用 Codex 会话桥；Superagent 主会话把需求交给 Router。
3. Router 根据项目能力创建工单、安排依赖和分工；并行 Worker 在各自隔离工作区执行。
4. Worker 可通过宿主传递消息。登记作业运行独立检查，Watchdog 观察进展并提出纠偏。
5. 工单记录结果、失败和待决事项，用户审核交付。生成文件保存在运行工作区，不自动替换项目原文件。

核心状态使用 SQLite，外部进程使用独立调用身份、心跳和终止回执。异常退出无法确认的执行进入待核对状态，不直接假定成功或再次执行。Router/Worker/Watchdog 有各自调用预算；页面“暂停”只暂停编排，不应冻结普通聊天。

## 复用与适配

| 层次 | 处理方式 |
| --- | --- |
| DSH 领域模型、状态、限额和原前端 | 固定版本源码保留在 vendor，记录原始哈希 |
| 存储与路由工具 | adapted 中保留必要导入与宿主边界变更及差异记录 |
| 网页 API、会话与进程 | 使用本地 Node/Python 宿主适配 Codex app-server / exec |
| Watchdog、项目输入和验收 | 本地扩展；不宣称全部来自上游 |

网页与 Codex 桌面应用不是同一个聊天 UI。这个项目启动独立本地 Web 宿主，调用安装好的 Codex CLI，按明确 thread/session ID 续接；不依赖桌面聊天窗口自动回话。

## 当前文件访问与独立执行

借鉴 DSH `src/app/sessions.ts` 的持久会话/工具和 `src/executor/dsh.ts` 的每工单工作目录，Codex 通过本机 stdio MCP 提供 `project_list`、`project_search`、`project_read`。目录由宿主项目登记决定；文件在调用时读取，后续追问使用同一 Session 并重新获取新版。旧版输入快照保留作为历史记录，新任务仅生成项目访问清单。

Router、普通会话和审核 Worker 可读取；编辑 Worker 另外通过 `project_checkout` 按需复制文件到每工单独立目录，使用 Codex 原生文件/命令工具修改和测试。已存在的工作副本不自动覆盖，需要与新源文件比较后合并。当前不是完整 Git worktree/自动合并实现，也不自动写回源目录。

每个回合的 `workspace-access/access.jsonl` 保存工具操作、文件 SHA256 与分页信息，`versions/` 保存实际读取字节。原始 App Server 事件保存命令与测试回执。项目 MCP 拒绝越界、链接、隐藏配置及凭据路径；本地执行仍受 Codex workspace-write 沙箱和无网络设置约束。读取范围由 MCP 检查，不能将原生命令的操作系统读权限说成项目级强隔离。

真实合成验收覆盖旧的无工具会话升级、同 Session 读取更新的 Word 和新增文件、独立副本修改及真实测试；完整编排验收还覆盖登记项目的 Router/Worker 和同工单追问。每次 Codex 升级仍需重新认证。

## 当前限制

- 普通聊天以文本为主，完整终端、文件树、附件处理、插件与计划任务未移植。
- GitHub/飞书渠道、完整规则模式、每角色独立模型与自定义 prepare/环境策略尚未接通。
- 项目读取有单文件 20 MB、格式和分页限制；不是无限上下文。DOCX 等提取正文，不等于完整排版或图像理解。
- 登记项目的 artifact-write 使用独立目录中的原生工具；旧的固定输入能力仍使用结构化文件交付，不扩大其原有授权。
- 普通会话当前可以读取项目文件，尚未接入与编辑 Worker 相同的修改/运行流程。旧显式 workspace-write 能力仍有独立兼容性门槛。
- 16 是可配置调度容量，真实模型负载受账号限流、机器资源与预算影响；不是 16 路性能保证。
- Windows 是当前验证平台，其他平台未验收；没有真实 FPGA、仪器或无人值守生产环境认证。
