# 功能与架构

## 一条任务如何执行

1. 浏览器连接本地 HTTP 宿主，访问工作区和持久会话。
2. 普通聊天直接使用 Codex 会话桥；Superagent 主会话把需求交给 Router。
3. Router 根据项目能力创建工单、安排依赖和分工；并行 Worker 在各自隔离工作区执行。
4. Worker 可通过宿主传递消息。登记作业运行独立检查，Watchdog 观察进展并提出纠偏。
5. 工单记录结果、失败和待决事项，用户审核交付。生成文件保存在运行工作区，不自动替换项目原文件。

核心状态使用 SQLite，外部进程使用独立调用身份、心跳和终止回执。异常退出无法确认的执行进入待核对状态，不直接假定成功或再次执行。Router/Worker/Watchdog 有各自调用预算；页面“暂停”只暂停编排，不应冻结普通聊天。

## 复用与适配

| 层次 | 处理方式 |
| --- | --- |
| DSH 领域模型、状态、限额和原前端 | 固定版本源码保留在 vendor，记录原始哈希 |
| 存储与路由工具 | adapted 中保留必要导入与宿主边界变更及差异记录 |
| 网页 API、会话与进程 | 使用本地 Node/Python 宿主适配 Codex app-server / exec |
| Watchdog、项目输入和验收 | 本地扩展；不宣称全部来自上游 |

网页与 Codex 桌面应用不是同一个聊天 UI。这个项目启动独立本地 Web 宿主，调用安装好的 Codex CLI，按明确 thread/session ID 续接；不依赖桌面聊天窗口自动回话。

## 当前限制

- 普通聊天以文本为主，完整终端、文件树、附件处理、插件与计划任务未移植。
- GitHub/飞书渠道、完整规则模式、每角色独立模型与自定义 prepare/环境策略尚未接通。
- 新项目输入会限制数量、大小和文件格式，并报告遗漏；不是无限上下文或完整工作目录挂载。
- 普通 artifact-write 模式由模型返回结构化文件，由宿主校验后写入隔离工作区；不是无限制终端 Agent。
- workspace-write 有独立的兼容性验收门槛，默认新增项目不开放该能力。
- 16 是可配置调度容量，真实模型负载受账号限流、机器资源与预算影响；不是 16 路性能保证。
- Windows 是当前验证平台，其他平台未验收；没有真实 FPGA、仪器或无人值守生产环境认证。
